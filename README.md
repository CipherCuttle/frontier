# FRONTIER

FRONTIER is a public, non-personalized, point-in-time intelligence terminal for emerging technology, software, research, crypto, markets, and security.

## Current state

The repository has moved beyond bootstrap:
- canonical governance / architecture authority is merged;
- the append-only PostgreSQL evidence substrate is merged;
- hostile acquisition / normalization preflight authority is merged;
- executable fetch/source contracts are merged;
- live acquisition V0 is merged with PyPI Latest Updates and CISA KEV as the first production source lanes.

The next product priority is source diversity: add structurally different ATTENTION / DISCOVERY evidence lanes before authorizing sophisticated ranking.

See `docs/ROADMAP.md` for current implementation state and sequencing.
See `docs/PLANNING_INDEX.md` for governance authority and precedence.

## Core rules

- Observation is evidence/assertion, not truth.
- `observed_at` is the FRONTIER knowledge horizon.
- Missing data is not observed absence.
- Emergence, confirmation, confidence, coverage and manipulation/reflexivity are distinct dimensions.
- No mandatory paid data/model APIs.
- No LLM in the canonical ranking/truth path.
- `frontier-fetch` is a hostile trust boundary and has no canonical database authority.
- Derived intelligence must be versioned, replayable and compared prospectively against a naive baseline before advanced ranking earns authority.
